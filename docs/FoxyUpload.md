# FoxyUpload — отправка треков и путевых точек из FoxyXplorer на FTP-сервер

FoxyUpload — встроенный в FoxyXplorer клиент **обычного FTP без шифрования**. Он сохраняет выбранные треки и путевые точки в локальной папке комплекта `10-Tracks`, а затем отправляет полученные файлы на FTP-сервер. При необходимости в удалённую папку также передаётся GPX-сетка комплекта. Отдельный FTP-клиент для обычной отправки не нужен.

**Состояние проверки:** три модульных теста FoxyUpload (проверка FTP-параметров, имён файлов и имени удалённой папки) успешно пройдены. Практическая проверка передачи файлов на FTP-сервер и работы на всех поддерживаемых ОС в рамках этого документа **не подтверждена**.

## Быстрый старт

1. Откройте нужный **комплект** в FoxyXplorer. Все отправляемые PLT/WPT должны сохраняться в его папку `<комплект>/10-Tracks`.
2. Откройте **Настройки (Settings)**. По умолчанию FoxyUpload выключен и представлен строкой **«FoxyUpload отключен»** с пустым чекбоксом. Установите флажок.
3. Заполните **FTP server** (только имя хоста или IP, без `ftp://`), **FTP port** (обычно `21`), **FTP login** и **FTP password**. Нажмите **Применить (Apply)**.
4. Выделите треки в правом списке и нажмите кнопку **Cloud Upload** в его нижней панели. Для путевых точек выделите точки, нажмите **Cloud Upload**, а затем выберите **WPT** или **WPT+**.
5. В окне подтверждения укажите **имя папки на FTP-сервере** (например, `2026-01-01_Shambala`). 
6. Проверьте данные и нажмите **«Сохранить и отправить»**. FoxyXplorer сначала сохранит PLT/WPT **на диск**, затем начнёт загрузку. При нажатии **«Отмена»** операция не выполняется.
7. Дождитесь итогового окна. В нём показано число переданных файлов, сведения о сетке и, при неудаче, список файлов с ошибками. Закройте окно кнопкой **«Закрыть»**.

**Важно:** пока идёт FTP-передача, окно хода выполнения не предназначено для отмены задачи. Не запускайте повторную отправку, пока не получен итоговый результат.

## Кнопки и режимы отправки

В нижних панелях обоих списков используется значок **облака со стрелкой вверх** (`CLOUD_UPLOAD`). При выключенном FoxyUpload обе кнопки скрыты; при включённом, но без выделения или открытого комплекта, они недоступны. Значок **стрелки вниз** (`DOWNLOAD`) в верхней панели относится к **FoxyDrop** — это [отдельный модуль приёма файлов по локальной сети](FoxyDrop.md).

| Список    | Действие                | Что происходит                                                                                                                     |
| --------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Треки** | **Cloud Upload**        | Каждый выбранный трек сохраняется в отдельный файл `.plt` и передаётся на FTP.                                                     |
| **Точки** | **Cloud Upload → WPT**  | Открывается диалог сохранения нового `.wpt`; выбранные точки записываются в файл и передаются на FTP.                              |
| **Точки** | **Cloud Upload → WPT+** | Открывается диалог выбора существующего `.wpt`; выбранные точки добавляются в него, после чего обновлённый файл передаётся на FTP. |

Кнопка **WPT+** меняет существующий **локальный** файл. Используйте её, только если действительно требуется дополнить этот WPT. Обычная кнопка **Save** в списках продолжает работать независимо от FoxyUpload.

### Сохранение треков (PLT)

- Файлы создаются в `<комплект>/10-Tracks`.
- Имя каждого PLT берётся из **Description** трека, если оно заполнено; иначе — из имени трека. К имени добавляется расширение `.plt`.
- Недопустимые для имени файла символы заменяются подчёркиванием. Если у нескольких выделенных треков получаются одинаковые имена, операция останавливается с ошибкой **до записи PLT**.
- Если в `10-Tracks` уже есть файл с тем же именем, локальное сохранение может заменить его. Перед отправкой проверьте имена треков и описания.

### Сохранение точек (WPT и WPT+)

- Для нового WPT предлагается имя вида `Waypoints_YYYYMMDD.wpt`; его можно изменить в диалоге сохранения.
- Для WPT+ пользователь выбирает уже существующий WPT из папки `10-Tracks`.
- Выбор файла **вне** папки `10-Tracks` не допускается. Передаются только файлы `.wpt`.
- При WPT+ FoxyXplorer сначала загружает существующий файл, добавляет выделенные точки и сохраняет результат. Если исходный файл не удалось прочитать, операция прерывается; старый файл не должен заменяться пустым новым.
- При сетевых повторах **WPT+ не выполняется повторно**: передаётся уже сохранённый локальный WPT.

**Внимание при ручном повторе:** если WPT+ уже успешно сохранён локально, но FTP-загрузка закончилась неудачей, **не запускайте WPT+ повторно с теми же точками** — это снова добавит их в файл. Передайте сохранённый WPT на сервер вручную обычным FTP-клиентом.

## Папка на сервере и GPX-сетка

При первой успешной связи с сервером FoxyUpload переходит в указанную пользователем папку. Если её нет, он пытается создать её командой FTP `MKD`. Имя папки может содержать обычные символы, но **не должно** быть пустым, содержать `/`, `\`, управляющие символы или быть равно `.` / `..`; вложенные пути вроде `Expedition/Day1` не поддерживаются.

Перед отправкой PLT/WPT FoxyXplorer ищет в локальной `10-Tracks` GPX-файл, который распознаётся как сетка с узлами. Если такая сетка найдена:

1. Проверяется наличие любого файла `.gpx` в удалённом каталоге.
2. Если GPX уже существует, **удалённая сетка не изменяется**, даже когда имя отличается от локального.
3. Если GPX нет, отправляется локальная сетка.
4. Если проверить наличие сетки безопасно не удаётся, операция с сеткой завершится ошибкой; программа не должна намеренно заменять неизвестную существующую сетку.

Для проверки используется список файлов FTP (`NLST`); при неподдерживаемом `NLST` предусмотрена ограниченная проверка `SIZE` для имени локальной сетки. Сетка передаётся как обычный GPX-файл, без изменения его содержания. Если в `10-Tracks` не найдено подходящей GPX-сетки, отправка PLT/WPT выполняется без неё.

## Замена файлов на FTP-сервере

Для каждого PLT и WPT выполняется согласованная последовательность:

1. Полностью сформировать и закрыть **локальный** файл.
2. Подключиться к FTP и перейти в папку комплекта.
3. Выполнить `DELE` для одноимённого файла на сервере. Ответ «файл не найден» не препятствует загрузке.
4. Выполнить `STOR` **сразу под окончательным именем** (`.plt` или `.wpt`). Временные имена вроде `.uploading` не используются.
5. Дождаться ответа FTP об окончании передачи. Если сервер поддерживает `SIZE`, дополнительно сравнить размер файла на сервере с локальным.

**Следствие выбранного механизма:** прежний удалённый файл может быть удалён до завершения загрузки нового. При обрыве соединения сервер может временно остаться без этого файла или содержать его неполную версию. Кроме того, веб-сервис, который постоянно читает FTP-каталог, теоретически может увидеть файл во время записи. Этот риск принят ради отсутствия временных файлов с нестандартными именами.

## Повторные попытки и сообщения об ошибках

Сетевая передача использует **до пяти попыток на каждый файл**, включая первую. Для каждой попытки выполняется новое FTP-подключение. При временной ошибке используется следующий график:

| Попытка | Пауза перед ней |
| ------- | ---------------:|
| 1       | Нет             |
| 2       | 1 с             |
| 3       | 2 с             |
| 4       | 4 с             |
| 5       | 8 с             |

- Повторяется **только передача уже готового файла с диска**. Экспорт PLT и добавление точек в WPT+ при повторах не запускаются.
- Постоянные ошибки, например некорректные параметры подключения или отказ FTP-сервера в операции, могут остановить попытки раньше пятого раза.
- Если один файл передать не удалось, FoxyUpload фиксирует ошибку и продолжает обрабатывать остальные файлы очереди.
- В итоговом окне отображаются количество успешно отправленных файлов и ошибки с именами файлов. Если сетка уже была на сервере, это сообщается отдельно. Число переданных файлов **может включать GPX-сетку**, если она действительно загружалась.
- Если попытки исчерпаны, исправьте соединение или права на сервере и **отправьте оставшиеся файлы вручную** из `10-Tracks`. Автоматическая фоновая очередь отложенной отправки не создаётся.

## Где хранятся настройки

| Параметр                          | Место хранения                                                | Поведение                                                                                                           |
| --------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Включён / выключен FoxyUpload     | Глобальный пользовательский `config.json`, поле `ftp_enabled` | По умолчанию **`false`**; действует для приложения в целом.                                                         |
| FTP server, port, login, password | Системное хранилище учётных данных через `keyring`            | Сохраняется весь профиль подключения, **включая адрес сервера**. В `config.json` и файле сессии он не записывается. |
| Имя папки на FTP-сервере          | Файл сессии, поле `ftp_remote_folder`                         | Восстанавливается при открытии сессии. При смене комплекта в текущем приложении сбрасывается.                       |
| Локальная папка FoxyDrop          | Файл сессии, поле `foxydrop_folder`                           | Также перенесена из глобальных настроек в сессию; при смене комплекта сбрасывается.                                 |

На Linux настройки обычно находятся в каталоге `~/.config/foxy/` (`config.json` и `session.json`); конкретный путь определяется системными каталогами пользователя. Пример **фрагмента** глобальной конфигурации:

```json
{
  "ftp_enabled": true
}
```

**При отключении** FoxyUpload его блок в Settings сворачивается в одну строку, а кнопки отправки скрываются. **Профиль FTP и имя удалённой папки не удаляются.** После повторного включения они восстанавливаются из соответствующих хранилищ. В поле **FTP password** ранее сохранённый пароль **не показывается**: пустое поле означает «оставить сохранённый пароль», если он уже существует.

Для работы системного хранилища на Linux обычно нужен доступный **Secret Service** (например, GNOME Keyring или KWallet) и работающая пользовательская D-Bus-сессия. В Windows используется системное хранилище учётных данных, в macOS — Keychain. Если хранилище недоступно, FoxyUpload сообщает об ошибке; незашифрованное сохранение пароля в `config.json` как запасной вариант **не предусмотрено**.

## Безопасность и требования к сети

FoxyUpload использует **обычный FTP без TLS**: пароль, команды и файлы передаются по сети **в открытом виде**, даже если реквизиты защищены системным хранилищем на диске. Используйте его только с доверенным FTP-сервером и в сети, для которой приемлем такой риск. Включение модуля не меняет настройки брандмауэра.

Клиент использует **пассивный FTP**: сначала `EPSV`, а при необходимости `PASV`. Для работы требуются доступ к управляющему порту сервера (обычно TCP 21) **и возможность устанавливать соединения с пассивными портами**, выдаваемыми сервером. Если логин проходит, но `STOR` или `NLST` не работают, проверьте настройки пассивного режима FTP-сервера, брандмауэра, NAT и VPN.

Протоколы **FTPS и SFTP в этой реализации не поддерживаются**. FTP-сервер должен разрешать авторизацию, создание/открытие целевой папки, удаление и запись файлов; для корректной работы с сеткой желательно поддерживать `NLST` и `SIZE`.

## Если загрузка не работает

| Симптом                                                                | Что проверить                                                                                                     |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Кнопки Cloud Upload отсутствуют                                        | Включён ли FoxyUpload в Settings и нажато ли **Применить**.                                                       |
| Кнопка недоступна                                                      | Открыт ли комплект, выделены ли треки или точки.                                                                  |
| «FTP не настроен»                                                      | Сохранён ли профиль подключения в Settings, доступно ли системное хранилище паролей.                              |
| «Неверный логин или пароль» / код FTP `530`                            | FTP-логин, пароль и права пользователя.                                                                           |
| Ошибка DNS или подключения                                             | Имя сервера (без `ftp://`), порт, доступность сервера и сети.                                                     |
| Соединение есть, но передача или получение списка файлов не удаётся    | Пассивные порты сервера (`EPSV`/`PASV`), NAT и брандмауэр.                                                        |
| Не создаётся папка FTP                                                 | Разрешено ли пользователю создавать каталог; корректно ли введено **простое имя папки**.                          |
| Не загружается сетка                                                   | Есть ли локальный GPX с узлами; работает ли проверка `NLST`/`SIZE`; нет ли уже GPX в удалённой папке.             |
| Ошибка при WPT+                                                        | Существует ли исходный WPT в `10-Tracks`, доступен ли он для чтения и записи.                                     |
| После пяти попыток не все файлы переданы                               | Посмотрите список ошибок. Локальные файлы остаются в `10-Tracks`; отправьте их вручную после устранения проблемы. |
| После неудачи WPT+ точки оказались в локальном файле, но не на сервере | Это ожидаемо: сохранение уже произошло. **Не повторяйте WPT+** с теми же точками — загрузите готовый WPT вручную. |

## Совместимость и проверка

| Проверка                                      | Состояние                                                                                                 |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Модульные тесты валидации FoxyUpload          | **3 теста пройдены** (по результату локального `cargo test`).                                             |
| Реальная передача PLT/WPT и повторные попытки | **Требуется практическая проверка** на FTP-сервере.                                                       |
| Linux (включая AppImage)                      | Требуется проверка сборки с системными зависимостями D-Bus и доступа к Secret Service на целевой системе. |
| Windows / macOS                               | Работа FTP и системного хранилища в поставляемых сборках отдельно **не подтверждена**.                    |

Для первой проверки используйте **отдельную пустую папку FTP**, в которой нет ценных файлов: отправьте один PLT, замените его повторной загрузкой, проверьте передачу сетки, затем WPT и WPT+. После этого полезно искусственно разорвать соединение и убедиться, что при ошибке FoxyXplorer показывает имя неотправленного файла, а локальная копия остаётся в `10-Tracks`.
